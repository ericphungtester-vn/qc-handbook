Gọi đúng tên, test đủ trạng thái

Tài liệu tra cứu nhanh cho QC: mỗi thành phần giao diện có tên chuẩn tiếng Anh (để báo bug/viết test case dev hiểu ngay), tên Việt, và danh sách cần test. Gõ vào ô tìm kiếm để lọc tức thì.

Phần lớn bug nằm ở trạng thái (state) của cùng một element, không phải ở lúc bình thường — nhớ test đủ các state ở mục Trạng thái, và dùng bộ dữ liệu test mẫu cho mọi ô nhập.

Mỗi thẻ có dòng API cho biết component đó thường gọi loại request nào — GET đọc dữ liệu, POST tạo mới, PUT/PATCH cập nhật, DELETE xoá, — chỉ hiển thị (không gọi API) — kèm gợi ý cần kiểm tra phía server.

loading

empty

Đây là tầng hành vi / hiệu năng — không phải component, nhưng ảnh hưởng trực tiếp trải nghiệm. Chúng thường đi kèm Skeleton, Spinner, Scroll area, Image. Điểm QC cốt lõi: không nhảy layout, không gọi trùng, xử lý lỗi/rollback rõ ràng, và luôn có lối cho bàn phím / screen reader.

Các tầng kỹ thuật (kiến trúc web)

Web architecture layers — theo đường đi của request
#TầngGồm gìQC / nhóm cần biết
1Client / FrontendTrình duyệt, UI, render (CSR/SSR) — HTML/CSS/JS, React/Vue…Chính là phần handbook này tập trung (tầng 2–8 để phối hợp)
2Delivery / NetworkDNS, CDN, TLS/HTTPS, load balancer, API gatewayHTTPS hợp lệ; không mixed content; cache/CDN xoá đúng sau deploy
3Backend / ApplicationServer; API REST/GraphQL; business logic; xác thựcTest API trực tiếp (Postman): mã lỗi, phân quyền, validate server, biên dữ liệu
4DataCSDL (SQL/NoSQL); cache (Redis); search index; lưu file/đối tượngDữ liệu đúng sau thao tác; ràng buộc; tìm kiếm đúng (kể cả tiếng Việt); không mất dữ liệu
5Integration / Dịch vụ ngoàiThanh toán, email/SMS, bản đồ, API bên thứ baXem mục Thanh toán & Email; test khi dịch vụ lỗi/timeout, webhook
6Infrastructure / DevOpsHosting/cloud, container, CI/CD, orchestrationDeploy đúng bản & đúng môi trường (xem Môi trường & phát hành)
7ObservabilityLogging, monitoring, error tracking, uptime, APMLỗi được ghi nhận & cảnh báo; theo dõi sự cố
8Security (xuyên suốt)Auth, mã hoá, WAF, secrets — phủ mọi tầngXem Bảo mật UI; không lộ secret phía client; phân quyền server

Đường đi request: Client (1) → Delivery (2) → Backend (3) → đọc/ghi Data (4) → gọi Dịch vụ ngoài (5); tất cả chạy trên Infra (6), được Observability (7) giám sát & Security (8) bảo vệ. Tầng 2–8 ngoài phạm vi UI/QC giao diện — đưa vào để nắm bức tranh tổng thể; chi tiết nên có tài liệu riêng.

Test case

Bộ test case theo 2 chế độ: Theo Component (sinh từ checklist của các component) và Theo Feature (Login, API GET/POST/PUT/PATCH/DELETE, Thanh toán, Đăng nhập & phiên, a11y…). Lọc theo Feature/Component, Hạng mục, Layer, Ưu tiên hoặc từ khoá; bấm ⋯ để xem Bước thực hiện; Xuất CSV để nhập vào Excel / công cụ quản lý test. Với component, nhớ chạy kèm mục Checklist nền (tab Sổ tay).
